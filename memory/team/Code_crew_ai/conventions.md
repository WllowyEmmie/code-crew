---
name: conventions
description: Coding style per language in this repo; every line says which language it applies to
---
- python: functions and variables are lowercase snake_case; classes are CamelCase
- python: every function has a one-line docstring saying what it returns
- python: strings are built with f-strings
- python: the repo has no pyproject.toml/ruff.toml, so ruff's default rule set applies (E4/E7/E9/F plus the harness's `--extend-select N`); E501 is NOT enabled, so a long one-line docstring (e.g. text_utils.is_palindrome's) passes lint and `ruff format` won't wrap it — don't hand-wrap it
- python: ruff's TRY004 (enabled by the harness's `--extend-select N`) rejects `raise ValueError` for a wrong *type*; raise TypeError for non-int/non-str arguments and keep ValueError for bad values (roman.py does this)
- python: roman.py holds to_roman(n)/from_roman(s) for 1-3999; from_roman parses greedily over the value/symbol table then rejects anything whose canonical to_roman(total) differs from the input, which is what makes "IIII", "IC", "VX" and lowercase fail
- python: to_roman rejects bool explicitly (`isinstance(n, bool)` -> TypeError) even though bool subclasses int; the request only pins ValueError for bad *values*, so bool-as-wrong-type is the accepted reading
- python: test_roman.py (repo root, pytest) covers roman.py: symbol/subtractive/combined values, 1 and 3999 boundaries, 0/4000/negatives, non-canonical numerals, empty/whitespace/lowercase/non-numeral strings, and a full 1..3999 to_roman->from_roman round-trip; wrong argument types are asserted with `pytest.raises((TypeError, ValueError))` because the request only pins ValueError for bad *values*
- python: text_stats.py holds word_counts(text) -> dict of lowercase word counts and top_words(text, n) -> list of (word, count) tuples ranked by descending count then alphabetically; n < 1 raises ValueError, non-int n / non-str text raise TypeError (bool n is TypeError)
- python: text_stats.py defines a word as a maximal run of letters/digits via `re.compile(r"[^\W_]+")` on text.lower(), so punctuation and underscores separate words and "don't" counts as "don" + "t"; empty or punctuation-only text gives {} and top_words returns fewer than n pairs when there are fewer distinct words
- python: the request for top_words only says "the n most common words", so test_text_stats.py asserts order via `_words()`/`_counts()` helpers that accept either bare words or (word, count) pairs; the builder's tuple shape is not pinned by the request, so don't fail it over the shape
- python: tests must not hide their assertions behind a shape guard — `if counts[0] is not None: assert ...` passes vacuously when the shape differs; assert the shape explicitly or split into separate tests
- python: test_text_stats.py (repo root, pytest) covers word_counts (case folding, punctuation/underscore separation, empty/whitespace/punctuation-only, single word) and top_words (count order, alphabetical ties, n=1 and n=distinct boundaries, n > distinct words, empty text, ValueError for n in {0,-1,-100} including on empty text)
- python: lru.py holds LRUCache(capacity) backed by collections.OrderedDict: get(key) returns None when missing and move_to_end()s a hit (a get counts as a use), put(key, value) move_to_end()s an existing key and otherwise popitem(last=False)s the LRU entry when len >= capacity; __len__ returns the item count
- python: LRUCache validates capacity as `not isinstance(capacity, int) or isinstance(capacity, bool)` -> TypeError, then `capacity < 1` -> ValueError (the request only pins ValueError for capacity < 1; bool/str are wrong types, matching the roman.py reading)
- python: test_lru.py (repo root, pytest) covers LRUCache: miss returns None, put/get round-trip, LRU eviction, get counts as a use, a miss does not change recency, re-put updates in place and counts as a use, capacity 1, a longer eviction sequence, multi-key get reordering, any-type values/keys, ValueError for capacity in {0,-1,-100}, and `pytest.raises((TypeError, ValueError))` for str/None/float capacity
- python: the LRU request only says "get must count as a use"; test_lru.py also asserts that re-putting an existing key counts as a use (standard LRU, and lru.py move_to_end()s it), so don't fail that test as unspecified — but don't treat put-refreshes-recency as a hard requirement either
- python: when testing LRU recency, every get() and re-put reorders the cache — trace the recency list step by step and keep recency-sensitive assertions in their own test with a fresh cache, or an earlier get() in the same test silently changes which key gets evicted
- python: text_utils.py holds is_palindrome(s) -> bool: it keeps only `char.isalnum()` characters (so spaces, punctuation and underscores are dropped, and digits count as content: "12 21" is a palindrome), lowercases them, and compares the list with its reverse; "" and punctuation-only input return True, and a non-str argument raises TypeError (matching the roman.py/lru.py wrong-type reading)
- python: test_text_utils.py (repo root, pytest) covers is_palindrome: empty string, single char, even/odd palindromes, non-palindromes, case folding, spaces/tabs/newlines, punctuation (classic "A man, a plan, a canal: Panama", "Was it a car or a cat I saw?"), punctuation-only input, digits as content ("12 21" True, "123" False), underscore ignored ("_a_" True), bool return type, and `pytest.raises((TypeError, ValueError))` for None/int/float/list/tuple
- python: slugify.py holds slugify(text) -> str: `_NON_ALNUM = re.compile(r"[\W_]+")` (underscore excluded explicitly because \w includes it) is subbed with "-" on text.lower(), then `.strip("-")`; empty result (empty/whitespace/punctuation-only text) raises ValueError, non-str raises TypeError
- python: slugify is Unicode-aware (`\W` on str), so accented letters survive: "Café au lait" -> "café-au-lait"; digits are kept ("Top 10 Hits" -> "top-10-hits")
- python: slugify lowercases BEFORE substituting, so a character whose lowercase form adds a combining mark splits the slug: "İstanbul" -> "i-stanbul" (the combining dot is not alphanumeric). That follows the request literally; don't "fix" it or test it as "istanbul" without a request change
- python: test_slugify.py (repo root, pytest) covers slugify: lowercasing, single word, space/punctuation runs -> one hyphen, mixed separator runs ("a  ,, b" -> "a-b"), existing hyphens not doubled, underscore as separator, leading/trailing separators stripped, digits as content ("Python 3.11" -> "python-3-11"), Unicode letters kept, a hyphen-clean invariant loop (no leading/trailing/double hyphen), str return type, ValueError for empty/whitespace-only/punctuation-only input, and `pytest.raises((TypeError, ValueError))` for None/int/float/list/tuple
- rust: single library crate at the repo root (Cargo.toml + src/lib.rs); std only, no external crates (no network)
- rust: unit tests go in a `#[cfg(test)] mod tests` block in the same file; integration tests go in `tests/<name>.rs` (a root-level .rs file is NOT compiled by cargo test)
- rust: `cargo fmt --check` and `cargo clippy --offline --all-targets -- -D warnings` must be clean; unwrap() only in tests
- rust: commit Cargo.lock and a root .gitignore containing `/target`; the crate name is `scheduler` (package name = library name, so `scheduler::free_slots` resolves)
- rust: run `cargo fmt` (not hand edits) before git_commit — rustfmt collapses short array literals onto one line and adds a trailing comma
- rust: repo-facts' "existing test files live in: repo root" describes the Python tests; Rust integration tests still belong in `tests/` (test-writer added tests/free_slots.rs there and cargo test picked it up)
- rust: `scheduler::free_slots` validates in the order duration 0 -> day_start/day_end -> busy times, and a reversed busy interval is an error even when it lies entirely outside the day (the request makes "end before start" an unconditional error); tests/free_slots.rs asserts this
