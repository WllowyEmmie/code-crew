- reviewer found: test_hello.py on main fails `ruff check --extend-select N` with I001 (import block un-sorted: missing blank line after `from hello import greet`), so linting all .py files in the repo reports an error the branch did not cause.. Avoid: Lint only the files the branch changed; if test_hello.py is ever touched, run `ruff check --fix test_hello.py` (or `ruff format`) to add the blank line before committing. (sess_a5438f7700a6: reviewer finding)
- reviewer found: test_text_stats.py's test_top_words_counts_match_word_counts wraps its only assertions in `if counts[0] is not None:`, so if top_words ever returned bare words instead of (word, count) pairs the test would pass while asserting nothing.. Avoid: When a return shape is ambiguous, assert the shape explicitly (e.g. `assert isinstance(result[0], tuple)`) or split into two tests, instead of guarding the real assertions behind a conditional that can silently skip them. (sess_71cbc21f52bc: reviewer finding)
- reviewer found: test_text_stats.py first asserted word_counts("cat. cat, cat! (cat) [cat] {cat} cat; cat: cat?") == {"cat": 8}, but the string has 9 "cat" tokens; the test failed against correct code and the test-writer then changed the expectation to 9 (a legitimate correction, not a weakening).. Avoid: When a test expectation is a literal count, count the tokens in the input explicitly (or derive the expected value from the input) before committing; if a test fails, first check whether the expectation or the code is wrong, and say which in the summary. (sess_b7868af2730b: reviewer finding)
- builder found: I edited lru.py's capacity validation back and forth (TypeError-first -> try/except -> TypeError-first) and the harness refused the third edit with "you're going back and forth".. Avoid: Decide the validation order once from the request (wrong type -> TypeError, bad value -> ValueError, as roman.py does) and write it in a single edit; don't rewrite the same block to explore alternatives. (sess_35dd93d3f741: builder finding)
- test-writer found: In test_lru.py I asserted eviction order after calling cache.get() in earlier assertions: get('a') then get('b') promoted b to most-recently-used, so the next put evicted a, not b, and my own test failed.. Avoid: When testing an LRU cache, remember every get() (and re-put) changes recency order. Either do all recency-sensitive assertions last, or split into separate tests with a fresh cache per scenario, and trace the recency list step by step before writing the expected eviction. (sess_35dd93d3f741: test-writer finding)
