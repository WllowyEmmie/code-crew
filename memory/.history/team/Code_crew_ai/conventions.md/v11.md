---
name: conventions
description: Coding style per language in this repo; every line says which language it applies to
---
- python: functions and variables are lowercase snake_case; classes are CamelCase
- python: every function has a one-line docstring saying what it returns
- python: strings are built with f-strings
- python: ruff's TRY004 (enabled by the harness's `--extend-select N`) rejects `raise ValueError` for a wrong *type*; raise TypeError for non-int/non-str arguments and keep ValueError for bad values (roman.py does this)
- python: roman.py holds to_roman(n)/from_roman(s) for 1-3999; from_roman parses greedily over the value/symbol table then rejects anything whose canonical to_roman(total) differs from the input, which is what makes "IIII", "IC", "VX" and lowercase fail
- python: to_roman rejects bool explicitly (`isinstance(n, bool)` -> TypeError) even though bool subclasses int; the request only pins ValueError for bad *values*, so bool-as-wrong-type is the accepted reading
- python: test_roman.py (repo root, pytest) covers roman.py: symbol/subtractive/combined values, 1 and 3999 boundaries, 0/4000/negatives, non-canonical numerals, empty/whitespace/lowercase/non-numeral strings, and a full 1..3999 to_roman->from_roman round-trip; wrong argument types are asserted with `pytest.raises((TypeError, ValueError))` because the request only pins ValueError for bad *values*
- rust: single library crate at the repo root (Cargo.toml + src/lib.rs); std only, no external crates (no network)
- rust: unit tests go in a `#[cfg(test)] mod tests` block in the same file; integration tests go in `tests/<name>.rs` (a root-level .rs file is NOT compiled by cargo test)
- rust: `cargo fmt --check` and `cargo clippy --offline --all-targets -- -D warnings` must be clean; unwrap() only in tests
- rust: commit Cargo.lock and a root .gitignore containing `/target`; the crate name is `scheduler` (package name = library name, so `scheduler::free_slots` resolves)
- rust: run `cargo fmt` (not hand edits) before git_commit — rustfmt collapses short array literals onto one line and adds a trailing comma
- rust: repo-facts' "existing test files live in: repo root" describes the Python tests; Rust integration tests still belong in `tests/` (test-writer added tests/free_slots.rs there and cargo test picked it up)
- rust: `scheduler::free_slots` validates in the order duration 0 -> day_start/day_end -> busy times, and a reversed busy interval is an error even when it lies entirely outside the day (the request makes "end before start" an unconditional error); tests/free_slots.rs asserts this
