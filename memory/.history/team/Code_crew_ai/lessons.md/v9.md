- Every role (builder and test-writer alike): read memory first — memory_list, then memory_read or memory_grep the notes relevant to this task — before changing files; the harness refuses edits otherwise (sess_418118aaa560: test-writer#1 write_file error; sess_49a2fbbba189: test-writer#1 write_file error; sess_e1dc9c0eb80e: test-writer#1 write_file error; sess_dacd43311980: test-writer#1 write_file error; sess_b59da00208d3: builder#2 edit_file error; sess_89ae92b22468: test-writer#1 write_file error; sess_9837c802032f: test-writer#1 edit_file error; sess_d1f017b66e63: builder#1 write_file error "read memory first"; sess_14d5f3e6464c: test-writer#1 edit_file error, builder#2 edit_file error; sess_b5f8cd017184: test-writer#1 write_file error "read memory first")
- Every role: memory_write also needs a prior memory_read of that file; writing blind is refused with "already exists ... read it first" (sess_acb1dc39f481: builder#1 memory_write error on team/lessons.md)
- Every role: the finish summary must include a "Memory:" line naming the notes you applied (lessons, conventions, repo-facts) or "none relevant"; finish is rejected without it (sess_d1f017b66e63: builder#1 finish rejected by harness)
- Every role: always call finish when done — the harness nudges agents that stop without it, and a session whose reviewer never finished is recorded as failed (sess_52c2b6375503: harness nudge(s)) (sess_c805c037788c: harness nudge) (sess_b5f8cd017184: session outcome "failed: reviewer didn't finish")
- Every role: run_command only accepts a fixed allowlist (ls, cat, head, tail, wc, find, pytest, ruff check, ruff format, cargo test/build/check/fmt/clippy); anything else is rejected, so use the provided tools instead of shell workarounds (sess_dacd43311980: builder#1 run_command error "command not allowed"; sess_b5f8cd017184: reviewer#1 run_command error "command not allowed")
- Every role: when rewriting a shared memory file, keep the existing per-language facts and only re-scope their wording; re-read the file after editing and restore anything that was lost (sess_b5f8cd017184: reviewer finding)
- Every role: only run a language's linter on that language's files — `ruff check src/lib.rs` reports 666 bogus "invalid-syntax" errors and burns steps; use cargo fmt/clippy for Rust and ruff for .py (sess review of code-crew/add-scheduler-free-slots)
- reviewer: `ruff check --extend-select N` on ALL .py files reports a pre-existing I001 (un-sorted import block) in test_hello.py, which is unchanged on main — lint only the files the branch touched, otherwise you flag a problem the branch did not cause (sess review of code-crew/add-roman)
- reviewer: when the harness warns that the test-writer changed a test after it failed, recount the literal expectation against the input before approving — a corrected count (e.g. 8 -> 9 "cat" tokens in a 9-token string) is a legitimate fix, a loosened assertion is a hidden bug (sess review of code-crew/add-text-stats)
- reviewer: a test-writer "change" that only splits one test into two with a fresh cache per scenario is legitimate when the original test's own earlier get()/re-put invalidated its later eviction assertion — check that every original assertion survives verbatim in one of the new tests before approving (sess review of code-crew/add-lru-cache)
- builder: implement the requested behaviour fully — no stubs, no `pass`-only bodies (ruff PIE790 refuses them) and no `_`-prefixed unused parameters (the harness rejects finish as a placeholder); finishing on a stub makes the test-writer's tests fail and the harness loops the failure back to you (sess_b59da00208d3: builder#1 command failed, feedback loop, tests failed; sess_89ae92b22468: builder#1 command failed with PIE790 unnecessary `pass`, harness rejected builder#1 finish, free_slots() had no implementation; sess_acb1dc39f481: harness rejected builder#1 finish three times, free_slots() ignored `_calendars`, `_day_start`, `_day_end`, `_duration`; sess_14d5f3e6464c: builder#1 finished done with unused parameters, then feedback loop)
- builder: run the repo's test command (cargo test --offline) and fix compile errors before git_commit or finish(done); commits were blocked by an unused parameter under `-D warnings` and by "cannot assign twice to immutable variable" (sess_14d5f3e6464c: builder#1 command failed exit 101, builder#2 command failed exit 101) (sess_acb1dc39f481: builder#1 finished done after cargo check exited 101 with unused-variable errors)
- builder: "cargo: command not found" in your shell does not mean the crate cannot be built — git_commit runs `cargo test --offline` itself (see repo-facts), so write the crate and its tests and let git_commit verify instead of abandoning the task with no commit (sess_d1f017b66e63: builder#1 command failed exit 127, session ended with no commit)
- builder: when the harness sends back failing tests, change the implementation to satisfy them; re-finishing without a fix just repeats the loop (sess_b59da00208d3: feedback loop repeated)
- builder: when the same test keeps failing, stop editing back and forth — the harness refuses an edit that repeats or undoes an earlier one; re-read the failing assertion and the request, and if the test expects something the request doesn't say, keep the version that matches the request and finish('done') naming the wrong test (sess_14d5f3e6464c: edit_file error "you're going back and forth"; sess_acb1dc39f481: builder#1 edit_file error "this edit repeats or undoes one you already made")
- builder: handle empty input collections explicitly — with no calendars the whole day is free; a test failed because the implementation returned an empty vector (sess_14d5f3e6464c: feedback loop, test_empty_calendars)
- builder: when the request says intervals may overlap, touch or be unsorted, sort and merge them before computing gaps; a test failed because overlapping busy times produced extra free slots (sess_14d5f3e6464c: feedback loop, test_overlapping_busy_times)
- builder: contractions (it's, don't) — a regex like \b\w+\b splits them in two; decide how they're counted explicitly (sess_52c2b6375503: builder#2 commit refused because tests failed)
- builder and test-writer: run the formatter on your changed files before git_commit (python: `ruff format FILE` + `ruff check --fix FILE`; rust: `cargo fmt`); don't hand-edit to match the formatter's diff — quote style and a missing trailing newline kept commits refused until the formatter was run (sess_49a2fbbba189: builder#1 command failed, test-writer#1 git_commit refused twice; sess_dacd43311980: builder#1 git_commit refused, ruff format reported "would be reformatted"; sess_89ae92b22468: test-writer#1 git_commit refused twice; sess_b5f8cd017184: builder#1 command failed, cargo fmt --check diff; sess_e1dc9c0eb80e: builder#1 command failed three times, test-writer#1 git_commit refused twice)
- builder (python): a new Python file that is executable but has no shebang fails ruff EXE002 and blocks git_commit; make the file non-executable or add a shebang instead of retrying the commit unchanged (sess_dacd43311980: ruff EXE002 twice, git_commit refused)
- builder (rust): `-D warnings` turns an unused parameter into a hard error; use the parameter in the implementation instead of renaming it `_x` (sess_14d5f3e6464c: builder#1 command failed exit 101)
- builder (rust): `*x = ...` only compiles when x is a reference; for a plain `u32` binding assign directly, e.g. `prev_end = prev_end.max(...)` (sess_acb1dc39f481: builder#1 command failed three times with E0614 "type `u32` cannot be dereferenced")
- test-writer: commit your own tests before finish(pass); re-running the builder's tests was rejected (sess_52c2b6375503: harness rejected finish)
- test-writer: you may only write test files; edit_file on the implementation is refused, so when a test fails decide whether the test's expectation or the source is wrong and report the source bug instead of patching it (sess_89ae92b22468: test-writer#1 edit_file error, test failed with DID NOT RAISE ValueError)
- test-writer: don't read_file a test file before you have written it; it does not exist yet (sess_89ae92b22468: test-writer#1 read_file error)
- test-writer: when a literal expected count fails, recount the tokens in the input before changing the expectation — in test_text_stats.py the "cat" punctuation string has 9 tokens, so the original `== {"cat": 8}` was the bug and 9 is correct (sess_b7868af2730b)
- test-writer: count your own tests from the file, not from the whole-repo pytest total — `python3 -m pytest -q` reports every test in the repo, so "20 tests" in a summary was really 15 in test_lru.py plus 5 pre-existing (sess_35dd93d3f741)
